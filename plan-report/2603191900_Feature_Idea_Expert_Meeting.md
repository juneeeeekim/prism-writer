**회의 일자:** 2026-03-19
**참석자:** Senior Developer(진행), AI 제품 전략가, 에듀테크 전문가, SaaS PM, 풀스택 엔지니어, UX 리서처
**주제:** PrismLM 서비스 확장을 위한 **신규 기능 아이디어 브레인스토밍** 및 전문가 자문

---

## 0. 현행 시스템 분석 (Current State)

### 0.1 서비스 개요
PrismLM은 **RAG 기반 AI 글쓰기 어시스턴트**로, 사용자가 자신의 문서를 업로드하면 이를 분석하여 구조 제안, 피드백, AI 채팅을 제공하는 서비스입니다.

### 0.2 기술 스택
| 구분 | 기술 | 비고 |
|------|------|------|
| **Frontend** | Next.js 14 (App Router) | Vercel 배포 |
| **Database** | Supabase (PostgreSQL + pgvector) | 서울 리전 |
| **LLM** | Google Gemini 3 Flash (기본) | GPT-5-mini, Claude 폴백 |
| **Embedding** | OpenAI text-embedding-3-small | 1536차원 |
| **Editor** | TipTap + Markdown | Shadow Writer 포함 |

### 0.3 현재 구현된 핵심 기능
- ✅ 멀티 프로젝트 관리 (생성/삭제/휴지통)
- ✅ 문서 업로드 & 파싱 (PDF, DOCX, TXT, MD, 이미지 OCR)
- ✅ 하이브리드 RAG 검색 (벡터 + 키워드 + Self-RAG)
- ✅ AI 채팅 (스트리밍, 세션 관리, 웹 검색 연동)
- ✅ 평가 시스템 (단일/전체 평가, 루브릭 템플릿)
- ✅ Shadow Writer (자동완성)
- ✅ AI Structurer (구조 분석)
- ✅ Deep Scholar (외부 리서치)
- ✅ 관리자 기능 (템플릿 승인, 사용자 관리)

## 1. 전문가 패널 소개 및 제안

### 1.1 🤖 박서현 — AI/LLM 제품 전략가

**경력:** AI 제품 전략 10년, LLM 기반 서비스 설계, AI Writing Tool 컨설턴트

#### 제안: "AI 글쓰기 코치 페르소나" 시스템

사용자가 업로드한 문서에서 **저자 스타일을 학습한 맞춤형 글쓰기 코치**를 생성하는 기능.

**핵심 기능:**
- 업로드 문서에서 문체, 어투, 자주 쓰는 표현, 문장 구조 패턴 자동 추출
- "이 저자처럼 써줘" / "이 논문의 톤으로 피드백해줘" 등 페르소나 기반 대화
- 여러 문서를 조합한 "하이브리드 코치" 생성 가능
- 코치별 프로파일 저장 및 재사용

**시너지 분석:**
| 기존 자산 | 활용 방안 |
|-----------|-----------|
| `lib/rag/rubrics.ts` (패턴 추출) | rule mining, example mining → 스타일 프로파일 생성 |
| `document_chunks` 벡터 임베딩 | 검색용 → 스타일 분석용으로 확장 |
| `llm-usage-map.ts` 50+ 컨텍스트 | `coach.persona.feedback` 등 새 컨텍스트 추가 |
| LLM Gateway 싱글 엔트리 포인트 | 페르소나 프롬프트 주입 자연스럽게 통합 |

**예상 구현 난이도:** ⭐⭐⭐ (중간)
**기존 인프라 재활용률:** ~90%

---

### 1.2 📊 김도윤 — 에듀테크/학습 과학 전문가

**경력:** 서울대 교육공학 박사, 학습 분석(Learning Analytics) 7년 연구, AI 적응형 학습 플랫폼 설계

#### 제안: "글쓰기 성장 대시보드" (Writing Growth Analytics)

사용자의 글쓰기 실력이 **시간에 따라 어떻게 변하는지** 시각적으로 보여주는 분석 대시보드.

**핵심 기능:**
- 평가 결과 시계열 추적 (어휘 다양성, 논리 구조, 인용 품질 등)
- "지난달 대비 논리 구조 점수 23% 향상" 같은 인사이트 생성
- 취약점 기반 맞춤 연습 문제 추천
- 프로젝트 간 비교 분석
- 주간/월간 글쓰기 리포트

**시너지 분석:**
| 기존 자산 | 활용 방안 |
|-----------|-----------|
| `evaluations` 테이블 | 이미 쌓인 평가 데이터 → 시계열 집계 |
| `useEvaluation()` 훅 | 시계열 집계 API 추가 확장 |
| `/api/evaluations` 엔드포인트 | 집계 쿼리 추가로 대시보드 데이터 제공 |
| 루브릭 템플릿 시스템 | 평가 기준별 점수 트래킹 구조 이미 존재 |

**교육학적 근거:**
> 학습 과학에서 가장 강력한 동기부여 메커니즘은 **"성장의 가시화"**입니다. 현재는 "이번 글은 어떤가"만 보여주고, "내가 얼마나 성장했는가"는 보여주지 않습니다. 성장 곡선을 시각화하면 사용자 리텐션이 크게 향상됩니다.

**예상 구현 난이도:** ⭐⭐ (낮음~중간)
**기존 인프라 재활용률:** ~95% (DB 구조 변경 불필요)

### 1.3 🤝 이정아 — 협업 도구/SaaS 프로덕트 매니저

**경력:** Notion, Figma 등 협업 도구 PM 5년, B2B SaaS 전략 컨설팅

#### 제안: "팀 프로젝트 & 공유 템플릿 마켓플레이스"

프로젝트를 팀원과 공유하고, 루브릭 템플릿을 커뮤니티에서 공유하는 생태계.

**핵심 기능:**
- 프로젝트 팀 공유 및 역할 부여 (편집자/검토자/뷰어)
- 커뮤니티 템플릿 마켓플레이스 ("학술 논문용", "기술 블로그용" 등)
- 팀장의 팀원 글쓰기 성장 모니터링

**시너지 분석:**
| 기존 자산 | 활용 방안 |
|-----------|-----------|
| `templates` 테이블 + 관리자 승인 | `is_public` 플래그 활용 → 마켓플레이스 |
| `projects` 테이블 | `shared_with` 관계 테이블 추가 |
| RBAC (`admin`/`user`) | `editor`/`reviewer` 역할 추가 |

**예상 구현 난이도:** ⭐⭐⭐⭐ (높음)
**기존 인프라 재활용률:** ~70%

### 1.4 🔧 최민호 — 풀스택 엔지니어/DX 전문가

**경력:** Next.js 코어 팀 기여자 출신, DX/성능 최적화 전문, 다수 SaaS 운영

#### 제안: "버전 히스토리 & 롤백 시스템"

문서의 변경 이력을 자동 관리하고, 특정 시점으로 롤백할 수 있는 기능.

**핵심 기능:**
- 자동 저장 시점마다 스냅샷 자동 생성
- "3일 전 버전"으로 복원 가능
- 변경 내역 diff 보기 (수정된 부분 하이라이트)
- AI 평가 결과와 버전을 연결 — "이 버전에서 점수가 올랐다"

**시너지 분석:**
| 기존 자산 | 활용 방안 |
|-----------|-----------|
| `useAutosave()` 훅 | 저장 시점에 스냅샷 트리거 추가 |
| Supabase PostgreSQL | `document_versions` 테이블 추가 |
| `evaluations` 테이블 | 버전 ID 컬럼 추가로 평가-버전 연결 |

**기술적 근거:**
> 현재 `useAutosave()`가 자동 저장을 수행하지만 이전 버전을 볼 수 있는 방법이 없습니다. 사용자가 실수로 좋은 문장을 지웠을 때 복구할 수 없는 것이 가장 큰 UX 리스크입니다.

**예상 구현 난이도:** ⭐⭐ (낮음~중간)
**기존 인프라 재활용률:** ~85%

### 1.5 🎨 한유진 — UX 리서처/접근성 전문가

**경력:** 사용자 조사 및 접근성(A11y) 8년, 글쓰기 도구 인지 부하 최소화 연구

#### 제안: "집중 모드 & 스마트 알림"

글쓰기 중 AI 기능이 방해가 되지 않도록 **맥락에 맞게 자동 조절**하는 UX 시스템.

**핵심 기능:**
- **집중 모드**: 에디터 전체화면, AI 패널 숨김, Shadow Writer만 활성화
- **흐름 감지**: 빠른 타이핑 중 AI 제안 억제
- **스마트 브레이크**: 글쓰기 시간/분량 요약 + 휴식 권유
- **단계별 가이드**: 초보자 순차 안내, 숙련자 단축키 중심

**시너지 분석:**
| 기존 자산 | 활용 방안 |
|-----------|-----------|
| `featureFlags.ts` | 사용자별 프로파일 기반 플래그로 확장 |
| Onboarding 시스템 | 단계적 기능 공개와 연결 |
| 6개 어시스턴트 탭 | 집중 모드 시 자동 숨김/표시 |

**예상 구현 난이도:** ⭐⭐ (낮음)
**기존 인프라 재활용률:** ~90%

## 2. 상호 검토 및 보완 (Cross-Review)

### 2.1 시너지 맵

```
AI 코치 페르소나 ←———→ 글쓰기 성장 대시보드
  (스타일 학습)           (성장 추적)
      ↕                       ↕
팀 협업/마켓플레이스 ←→ 버전 히스토리
  (공유 생태계)          (변경 추적)
      ↕                       ↕
        집중 모드 & 스마트 알림
          (사용성 최적화 기반)
```

### 2.2 크로스 시너지 상세

| 조합 | 시너지 효과 |
|------|------------|
| **버전 히스토리 + 성장 대시보드** | "이 수정 후 점수가 올랐다" → 성장 포인트 자동 식별 |
| **성장 대시보드 + AI 코치** | "당신은 논리 구조가 약하다" → 맞춤 코칭 제공 |
| **AI 코치 + 버전 히스토리** | "이전 버전보다 이 스타일이 더 맞다" → 근거 있는 피드백 |
| **팀 협업 + 성장 대시보드** | 팀장이 팀원 성장 모니터링 |
| **집중 모드 + 모든 기능** | 기능 과부하 방지, 사용성 기반 제공 |

## 4. 선택된 아이디어 및 구현 순서

### 디렉터 선정: 3가지 기능 채택

1. **AI 글쓰기 코치 페르소나**
2. **글쓰기 성장 대시보드**
3. **버전 히스토리**

### 권장 구현 순서

```
Phase A: 버전 히스토리 (기반 데이터 레이어)
├── document_versions 테이블 설계 및 마이그레이션
├── useAutosave() 훅에 스냅샷 트리거 추가
├── 버전 목록 UI + diff 뷰어
└── 평가 결과와 버전 연결 (version_id 컬럼)

Phase B: 글쓰기 성장 대시보드 (데이터 활용)
├── 평가 데이터 시계열 집계 API
├── 성장 곡선 차트 컴포넌트
├── 버전별 점수 변화 추적
├── 주간/월간 리포트 생성
└── 취약점 기반 인사이트

Phase C: AI 글쓰기 코치 페르소나 (지능 레이어)
├── 스타일 프로파일 추출 파이프라인
├── 페르소나 관리 UI (생성/편집/선택)
├── LLM Gateway에 페르소나 프롬프트 주입
├── 성장 데이터 기반 맞춤 코칭 로직
└── 하이브리드 코치 (다중 문서 조합)
```

**순서 근거:**
> **A → B → C** 순서의 이유: 버전 히스토리가 **데이터 기반**이 되어야 성장 대시보드에서 **버전별 비교 분석**이 가능하고, 이 데이터가 쌓여야 AI 코치가 **"당신은 이 부분이 성장했다"** 는 맞춤 피드백을 줄 수 있기 때문입니다.
